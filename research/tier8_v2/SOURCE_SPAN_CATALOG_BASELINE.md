# Catalog-only control: offline fitting result

The header attribution audit found all added numeric values already visible in
the original selected source span. A catalog-only baseline tests formal operand
availability without rewriting that source text. This is known source-pointer
engineering, not an adopted or novel QA method.

The pure transformation receives only the public evidence dictionary. It keeps
every old quantity ID/value/context, then appends missing `(source span, numeric
value)` pairs accepted by the executor's input range. It retains all eligible
spans instead of choosing the first match. New entries explicitly lack cell
localization or financial-role certification. Equal values within a span are
represented once; do not treat a singleton entry as a unique financial cell.

All 73 fitting catalogs were sealed before reference diagnostics. Original source
packets remain byte-unchanged. Results:

| Offline measure | Original | Header materialization | Catalog-only |
|---|---:|---:|---:|
| Reference programs numerically mappable |41/73|45/73|45/73|
| Selectable catalog occurrences |1,922|2,105|2,338|
| Extra direct-draft prompt tokens, total |0|5,418|5,597|

The same four questions recover under both variants, and every case has the same
parser category between them. All catalog-only quantities compile and execute
against the ORIGINAL source. Independently reloaded catalogs retain all old IDs
and source values; no previously mappable case is lost. This proves formal
representability/source support, not semantic relevance or answer accuracy.

Both 3B and 7B vocabulary-only profiles produce the displayed token totals. The
catalog-only median extra cost is 31 tokens and maximum 328; all 73 direct prompts
retain the full 768+8 reserve under 4,096 context. It uses fewer tokens than
materialization on 38 cases, equal tokens on nine, more on 26: **179 more overall**.
Do not claim aggregate prompt savings. Extra catalog options across multiple
spans can add distractors even though source text is unchanged.

Capture temporarily replaces the catalog function only inside the metadata
process, then stops before generation. No active pipeline source, worker, packet
or prepared neural command changes. This is not an integrated neural runner or a
new training corpus. No HF/SFT parity, full-policy context, neural QA gain or
architecture winner is established. Vocabulary-only runtime warnings are retained
in the raw log; no model forward occurred. Future neural work needs normal full
model/proof checks and explicit frozen configuration.

Three tests cover original ID/source preservation, executable header recovery,
all matching source spans, and avoiding unsupported new magnitudes. Results,
captured prompts and ledgers are pinned in [evidence](evidence/source-span-catalog-fitting-01.json).
The [catalog function](experiments/source_span_catalog.py) and
[offline experiment](experiments/source_span_catalog_fitting.py) are reproducible.
Neither baseline is adopted; the active matched neural study retains priority.
