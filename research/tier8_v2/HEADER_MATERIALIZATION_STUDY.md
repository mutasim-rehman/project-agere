# Controlled source-retention test, prepared but not run

The fitting-only prototype recovers reference operand coverage in four of73
questions without losing old catalog facts. This does not establish better
generation. Test that missing link before treating the preprocessing change as
a useful component of a research method. Known source-retention preprocessing
alone is not a first-use novelty claim.

Four complete73-case runs are prepared: original fitting packets versus sealed
header-materialized packets, separately for SAS and MAS. SAS uses the original
joint7B adapter. MAS uses the common3B actor and stronger original3B critic,
which preserves more correct deliveries than the crossed critic in the completed
selection study. These checkpoints are fixed before any new fitting neural result.
No checkpoint replacement or outcome-selected per-question routing is allowed.

Within each architecture, all settings/checkpoints remain identical except data
and output paths: direct draft, zero analysis/demos, binary review, full repair,
4096 context, the existing monitored6.4GB cap and scoring. A separate source copy
and selection namespace pass the existing runner's immutable partition checks.
The active study source/selection/packets/commands are unchanged. Every candidate
is independently regenerated from public packet plus raw table and compared to
the already sealed prototype. All73 cases remain; selection/reserved packets
are not transformed.

Primary question: does initial answer generation improve? Use measured ungated
initial-prefix reported and raw correctness, requiring no loss under either
convention and at least one strict gain, separately for each architecture. This
prefix comes from a full recorded trajectory, not an independently rerun draft.
Also report full delivery correctness/error/withholding, no-repair prefix, repairs,
tokens, latency, memory and whole-report uncertainty. Apply both existing metrics
unchanged. Never turn a reduction in delivered wrong answers alone into a claim
of better generation or hide a correct-answer loss against the original.

Candidate prompts contain extra source content and tokens. This is a drop-in
representation comparison with frozen checkpoints, not an information/token-
matched algorithmic comparison, a trained materialization policy, independent
semantic certification or publication confirmation. All73 fitting cases were
already explored structurally, so even a positive result remains exploratory.
Architecture results must remain separate; these runs do not choose a SAS/MAS
winner or establish either architecture's best achievable prompt configuration.

The proposed292 case-arms are NOT launched or added to the active sequence.
The original matched natural/baseline/reserved/secondary study must finish first.
Only then consider these serial monitored runs. Do not launch extra inference
alongside the current job or silently replace original scientific obligations.

[Preparation and analyzer](experiments/header_materialization_study.py) reuse
the full natural-trace auditor for source/prompt/adapter/proof, token/execution/
scoring and every memory sample. A representation-specific check permits only
the declared source transformation and refuses checkpoint/policy confounds.
Six standard-library tests pass, including rejection of missing cases, invented
source content and changed checkpoints. Completed neural traces are still absent;
tests are not evidence of QA gains. [Pinned preparation evidence](evidence/header-neural-fitting-plan-01.json).
