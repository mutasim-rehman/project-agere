# Source-aware repair candidate: development record

26October2026. This is a candidate and diagnostic record, not a demonstrated
contribution, completed evaluation or final cross-tier method freeze.

The question is whether a bounded verifier can spend its calls on meaningfully
different source-grounded formulas rather than repeated representations. Distinct
source IDs remain distinct even when their observed numbers coincide. Matching
numbers, citations or execution success alone do not establish financial relevance.

## Prior methods and narrow possible contribution

[LEVER](https://arxiv.org/abs/2302.08468) learns verification using input, program
and execution, combines generation and verification scores, and marginalizes
programs with the same execution result. [ProbeGen](https://arxiv.org/abs/2502.18473)
searches for program-equivalence counterexamples and uses semantic clustering for
self-consistency. These primary abstracts were read; full-method replication is
not complete. Generic execution reranking, verifier learning, semantic clustering,
symbolic algebra and forced-prefix label classification are established methods.
Do not claim they originate here or label the controls full LEVER/ProbeGen
replications. Existing novelty matrix has additional financial-verification,
source-binding and budget-allocation priors.

A possible narrower experiment concerns **safe reuse of fallible verdicts under
a strict work budget**: distinguish a source-symbolic identity from coincident
observed values, and test whether representative selection saves useful work.
It needs both a worthwhile effect and a full closest-prior review. Combining
existing pieces or finding a unit-test counterexample does not establish novelty.

## Implemented candidate

One public-evidence-only pool contains the initial draft, an optional actual
regeneration, then bounded local changes: operation, noncommutative operand order,
nearby source binding, and multiply/divide100 output scale. No gold or saved score
is consulted. No artificial algebraic rewrites or commutative swaps are inserted
to manufacture deduplication savings. Fixed hash order within families and round
robin between them, maximum64 programs; regenerate invalid drafts using the actor,
not a hidden reference program.

Four grouping controls share exactly the same pool and first representative rule:
byte-identical programs; observed numeric value plus answer unit; numeric value
plus unit and source footprint; bounded source-symbolic identity. The last uses
exact rational polynomial cross-products, matching source IDs, division conditions,
units AND current-document Decimal results. It does not prove global Decimal
equivalence or financial correctness. Each comparison is capped at100000 algebra
operations,2048 monomials,4096 coefficient bits; total partition work1000000
operations. Unknown/unsupported cases are never merged. Executable symbolic
unknowns remain individually scoreable. Conservative guard matching may miss
valid identities; it cannot be advertised as complete equivalence analysis.

Shared proposed scorer reads the actual native last-position PASS/FAIL/UNKNOWN
logits after the canonical training-response prefix. Actual GGUF vocabulary-only
checks show all three are one continuation token for both3B and7B tokenizers.
Full prompt-boundary checks also run on every scoring call. No all-position logits
allocation. The margin PASS minus max(FAIL,UNKNOWN) is not calibrated confidence.
This scorer still needs an actual monitored model parity/effect check before use.

Provisional identical verification allowance:8192 evaluated prompt/prefix tokens
and4 checks per case, context4096. Every forced-prefix token counts. Generations
retain the common2048 output ceiling. Report actual actor and critic prefill,
generated tokens, latency, symbolic work and full-tree RSS. A strictly positive
margin is required for delivery; higher margins win, original wins exact ties.
No duplicate voting. All controls get the same scorer; a forced-prefix improvement
cannot be attributed to source-symbolic grouping.

## First gold-free diagnostic and consequence

The already-used24 adapted-actor initial drafts produced370 executable candidates:
370 byte classes,332 numeric classes,360 numeric-plus-source classes,368 symbolic
classes. The first4 representative indices changed in only1/24 cases between byte
and symbolic grouping. No actual regeneration, verification, scores or target
answers entered this diagnostic. Raw snapshot files contain older metrics but the
diagnostic reads only case ID and initial reference plan; this is not fresh data.

This is **weak evidence for useful deduplication savings**. Do not make quotient
repair the central paper claim or spend a full benchmark on it solely because the
implementation exists. Numeric grouping merges substantially more candidates;
that is an ambiguity diagnostic, not proof that any merged answer is incorrect.
Keep these controls for a small natural-error discovery pilot after serial model
training. Continue only if actual regenerated pools show a useful opportunity.
Do not change the pool to manufacture duplicates after seeing this outcome.

17 targeted CPU checks pass, including distinct equal-valued sources, same-source
coincident results with different rational functions, division-domain cancellation,
Decimal rounding differences, work exhaustion, invalid drafts, stable ties and
both verification budget ceilings. This is implementation evidence, not QA gain.

Before any100-report outcome is used to select this method, write the actual
pilot conditions and stop rule, run the work-accounted controls, and report both
reported-answer and raw-execution correct/wrong/withheld. Natural training-source
packets are available for development;100-report public dev remains exploratory,
not an untouched confirmatory test. All methods carried to16/32GB must be frozen
after8GB evidence, with failed candidates retained in the research record.
